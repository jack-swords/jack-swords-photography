# Jack Swords Photography

Photography portfolio and story site. Next.js 16 (App Router, TypeScript) on Vercel, with Sanity as the CMS and image pipeline. Sanity Studio is embedded at `/studio`.

## Stack

| Concern | Choice |
|---|---|
| Framework | Next.js 16, App Router, TypeScript |
| CMS / database | Sanity Content Lake, Studio embedded at `/studio` |
| Images | Sanity asset CDN (`auto=format`, hotspot/crop, LQIP) |
| Styling | Tailwind CSS v4. Design tokens live in [`src/app/globals.css`](src/app/globals.css) (`@theme`) |
| Package manager | pnpm |

## Project layout

```
sanity.config.ts            Studio config (structure, singletons, plugins)
sanity.cli.ts               CLI + TypeGen config
scripts/seed.ts             Demo content generator
src/app/(site)/             Public site (own root layout)
src/app/studio/             Embedded Studio (own root layout)
src/sanity/env.ts           Env vars
src/sanity/lib/             Client, image URL builder, GROQ queries
src/sanity/schemaTypes/     Schemas: documents/, objects/, blocks/
src/sanity/structure.ts     Studio sidebar (orderable lists + singletons)
src/sanity/types.ts         Generated by `pnpm typegen`, don't edit
```

## First-time setup

1. **Install:** `pnpm install`
2. **Create the Sanity project** (one time):
   ```sh
   pnpm dlx sanity@latest init --bare   # or create one at https://www.sanity.io/manage
   ```
   Note the project ID. Use the `production` dataset.
3. **Env:** `cp .env.example .env.local` and fill in `NEXT_PUBLIC_SANITY_PROJECT_ID`.
4. **Tokens:** go to sanity.io/manage → your project → **API → Tokens**:
   - `SANITY_API_WRITE_TOKEN`: **Editor** permissions (seed and import scripts, programmatic updates)
   - `SANITY_API_READ_TOKEN`: **Viewer** permissions (draft previews, milestone 5)
5. **CORS:** in **API → CORS origins**, add `http://localhost:3000` and your Vercel URL(s), each with **Allow credentials** ticked. The embedded Studio needs this.
6. **Seed demo content:** `pnpm seed`. This adds 3 projects using every block type, 4 categories, settings, homepage and about. Add `--hero-video path/to/clip.mp4` to give "Night Swimmers" a video hero. `pnpm seed --dry-run` writes the images and JSON to `./seed-output` without touching Sanity.
7. **Run:** `pnpm dev`. The site is at http://localhost:3000 and the Studio at http://localhost:3000/studio.

## Deploying to Vercel

1. Import the GitHub repo in Vercel. The framework preset is auto-detected as Next.js, and pnpm is picked up from the lockfile.
2. Add the env vars from `.env.example` to the Vercel project for the Production and Preview environments.
3. Add the deployment URL to Sanity's CORS origins (step 5 above).

Every push to a branch gets a preview deployment.

|---|---|
| `pnpm dev` / `build` / `start` | Next.js |

## Content model

- **Singletons** (fixed IDs, no create/delete in Studio): `siteSettings`, `homepage`, `about`
- **`project`**: title, slug, subtitle, hero (image, or video file/URL plus poster), overlay text tone, credits, categories, date, `blocks`, next projects, SEO. Manual order via drag and drop in Studio (`orderRank`), with date as the fallback sort.
- **`category`**: title, slug, manual order
- **Blocks** (the `blocks` array on a project): `imageSingle`, `imageFullBleed`, `imagePair`, `imageGrid2x2`, `imageOffset`, `textBlock`, `spacer`. The text block is named `textBlock` because `text` is a built-in Sanity type.
- Every image uses the shared `photo` type: hotspot, required alt text, and a two-line caption (`caption`, `captionSecondary`). GPS location is never extracted into asset metadata.
- Image counts are derived in GROQ from the blocks (`imageCountFragment` in `src/sanity/lib/queries.ts`), never typed in.

## Updating content programmatically

Any script with an **Editor** token can write to the Content Lake:

```ts
import {createClient} from '@sanity/client'

const client = createClient({
  projectId: process.env.NEXT_PUBLIC_SANITY_PROJECT_ID,
  dataset: 'production',
  apiVersion: '2026-09-01',
  token: process.env.SANITY_API_WRITE_TOKEN,
  useCdn: false,
})

// Change a field on a published project
await client.patch('project-salt-flats').set({subtitle: 'New standfirst'}).commit()

// Append a single-image block to the end of the story
const asset = await client.assets.upload('image', fs.createReadStream('photo.jpg'))
await client
  .patch('project-salt-flats')
  .append('blocks', [
    {
      _type: 'imageSingle',
      _key: crypto.randomUUID(),
      width: 'medium',
      align: 'center',
      image: {_type: 'photo', asset: {_type: 'reference', _ref: asset._id}, alt: 'Describe the photo'},
    },
  ])
  .commit()
```

To stage a change as a draft instead of publishing it, patch `drafts.<id>` (create it first with `createIfNotExists`, copying the published document).
